# 可配置的 2–100 人轻量多人模板

`score-race-v1` 是平台维护的反应竞速玩法。服务器发给每位选手一个图形挑战，客户端回答对应目标；正确答案消耗该挑战、经过最短 150ms 冷却后才可再次计分，先达到 10 分的选手获胜。答案和操作可由程序自动生成，因此这只是可信规则执行示例，不是通用反作弊方案。

配置属于可信发行版能力清单，游戏客户端不能通过排队参数擅自改变对局规则：

```json
{
  "schemaVersion": "1.0",
  "sdkVersion": "0.1",
  "capabilities": ["profile", "matchmaking", "match"],
  "multiplayer": {
    "adapter": "score-race-v1",
    "minPlayers": 20,
    "maxPlayers": 20
  }
}
```

`minPlayers` 为开局门槛，`maxPlayers` 为该发行版对局上限。当前匹配器达到门槛就组局，没有额外等待凑满的计时器；`2/100` 通常两人就组局，固定百人应配置 `100/100`。可以注册多个游戏/发行版本使用不同人数配置，但每个玩家的队列仍按游戏/环境/发行版本隔离。

安装与启动见平台 README。本机种子入口：<http://127.0.0.1:7400/play/arcane-score-race>，默认 `minPlayers:2,maxPlayers:100`，两个独立浏览器身份即可体验。服务端公共 WebSocket 路径是 `/v1/score-race`，使用 `arcane-match-v1` 和 SDK 的 `createMatchConnection`；比赛票据通过 `sdk.match.ticket({matchRunId})` 领取。

输入仅为 `{answer:0..3,challengeId:string}`，没有任意分数/名次提交接口。名单必须全部入场才启动，120 秒未到齐弃赛、不发奖；开局 60 秒后按合法得分排序，分数相同按冻结名单顺序打破平局。排行榜及个人结果由后台持久结算。

服务端使用每房 20ms 的短输入窗口，按到达顺序校验这一批合法输入，只执行一次状态 CAS 持久化，然后向操作者返回 ACK。数据库写入失败时整批不更新内存状态、不返回成功 ACK；客户端旧输入不会自动重放。这样百人同时操作通常共享一次提交，避免串行执行 100 次完整 runtime/数据库往返。全房广播合并为最多 10Hz，结束状态立即广播；100 个同时到达的输入不会触发 10,000 次全量广播。

写入请求的响应丢失时，服务器会重新读取持久状态及版本进行对账；只有读到相同的已提交状态才确认 ACK。对账也暂不可用时，房间停止后续写入，之后的输入或后台恢复会先重读版本，避免一直使用旧版本产生 CAS 冲突。对账确认的已消费输入序号不会重复计分，已经冻结的结束结果仍由后台幂等结算，无需重启进程才能恢复。

入场始终验证持久会话；比赛连接复用最近最多 5 秒的成功会话检查，过期时并行检查不同玩家，后台每 5 秒强制复查。退出撤销最多可能有约 5 秒传播窗口，检查确认撤销后立即关连接；后台故障时沿用最多 10 秒的关闭宽限，但过期缓存的输入不会在验证失败时提交。连接输入队列最多 4 条、全房等待队列最多 400 条，超限连接会被关闭，避免数据库故障时无限堆积。

状态采用紧凑数组，100 人结束状态在单测中约 14KiB，低于 32KiB 持久状态限额。公开快照约 4.5KiB，持续变更时理论全房广播约 `4.5KiB×100×10 ≈ 4.4MiB/s`，还需加操作 ACK、TLS/WS 和心跳开销；真实环境应监控带宽及数据库延迟。

本机真实性能检查：

```sh
node platform/tools/multiplayer-load.mjs 100
```

该运维工具需先启动本机堆栈。它使用运维凭据预置测试账号，避免修改生产登录限流；之后通过 SDK 完成固定百人的排队、领取票据、真实 WS 入场、输入和结算，再核对真实数据库里的名单与最终结果。它保存的报告不含账号、票据或密钥，位于 `platform/.local-data/multiplayer-load-report.json`。回环测试结果不代表公网延迟，也不代表扫地机器人或任意物理玩法支持百人。

电脑/手机真实浏览器验收可单独运行，不需要 Robo 资源：

```sh
node platform/tools/score-race-browser.mjs
# 使用 Playwright 自带 Chromium（可用于 macOS/Linux 或没有 Chrome 的机器）：
npx playwright install chromium
node platform/tools/score-race-browser.mjs --chromium
```

脚本在隔离的临时游戏中，用两个浏览器身份完成匹配、19 次合法操作、双方结算与社区榜单检查，同时检查手机横向溢出和未捕获异常。脱敏报告及截图位于 `platform/.local-data/score-race-browser/`。该浏览器验收已在当前 Windows 电脑执行通过；macOS/Linux 命令已提供，未宣称在这台机器上实际运行了那些操作系统。

玩法服务器、模拟复杂度和硬件决定具体适配器能承载的人数。SDK/匹配层上限为 100，并不取消 `turn-based-v1` 双人规则或 Robo 的 12 人模拟限制；新玩法仍需平台维护的可信 authority。
