# Trusted operator commands

These tools run on a trusted operator machine with Node.js 22+. Run `--help` for all options. They never accept a player token or Nakama runtime key as a publishing credential. Execute commands from the repository root.

## Register and activate an immutable release

Set `ARCANE_PUBLIC_URL` to your trusted HTTPS gateway. Publish with either:

- `ARCANE_PUBLISH_TOKEN`: a publisher bearer token whose SHA-256 digest is mapped to an owner in the gateway's `ARCANE_PUBLISHER_KEYS`. The gateway selects the owner; omit `--publisher-id`.
- `ARCANE_ADMIN_TOKEN`: the platform operator credential. Supply `--publisher-id` when registering a release.

The following example reads the operator credential from the private `platform/.env` generated by `platform/examples/init-production-env.mjs`. Both commands are single lines and work in PowerShell, macOS Terminal and Linux shells:

```bash
node --env-file=platform/.env platform/tools/register-game.mjs --manifest platform/examples/take-away.manifest.json --game-id my-game --environment production --release-id r1 --build-hash BUILD_SHA256 --publisher-id my-publisher --entry-url https://game-content.example.net/my-game/r1/game.html
node --env-file=platform/.env platform/tools/register-game.mjs activate --game-id my-game --environment production --release-id r1 --build-hash BUILD_SHA256
```

Replace the IDs, content URL and `BUILD_SHA256` with your immutable build values. The content origin must be allowlisted separately from the trusted host origin. Production entry URLs must use HTTPS.

Registration stages with `activate:false`. The tool does **not** upload or verify static files: upload every immutable resource and verify its hashes before the activation command. Activation checks the registered build hash and moves the active release pointer. An exact retry is accepted; a conflicting existing release cannot be overwritten. Registration with `--activate` is available for trusted one-step setups where resources already exist.

Load the activated game at `https://play.example.com/play/my-game?environment=production&releaseId=r1`. The default `/play` scope is `development/dev`; production links must select their actual registered scope.

## Short-lived server workload credentials

Create these credentials only on a trusted platform operator host. Its `ARCANE_TOKEN_SECRET` must match the gateway; the signing secret stays on that host and is never given to an external authority or a browser game.

Prepare a private directory before running this example:

```powershell
# Windows PowerShell; apply an account ACL appropriate for your server user.
New-Item -ItemType Directory -Force platform/private
```

```bash
# macOS/Linux; execute as the trusted operator user.
mkdir -p platform/private
chmod 700 platform/private
```

Issue a new credential file:

```bash
node --env-file=platform/.env platform/tools/create-workload-token.mjs --game-id my-game --environment production --release-id r1 --adapter-id my-authority-v1 --subject game-server-1 --actions register,get,state,settle,consume --ttl-seconds 3600 --output platform/private/workload-r1.json
```

`my-authority-v1` is a placeholder for a trusted adapter you have implemented and integrated. Issuing a token does not install or register an adapter. Built-in authorities run in the gateway and do not require manual workload-file provisioning. See the [runtime contract](../nakama/CONTRACT.md) for state, ticket and settlement requirements.

The output JSON contains `token`, `expiresAt`, and its exact scope. Provision it securely to only the matching authoritative adapter, read its `token` field for server-to-gateway requests, and renew before expiry. Select only the actions the workload needs.

The tool refuses to overwrite a file or issue wildcard scopes/actions. Maximum TTL is 24 hours. Token and signing-secret values are never printed. POSIX files are created with mode `0600`; on Windows use protected directory/account ACLs. Do not commit or attach the file to an Issue, and do not put bearer values on command lines.

For renewal, issue to a new file and atomically replace the provisioned credential according to the consuming authority's reload contract. This version has no automatic renewal API. Server workload tokens never belong in client bundles; browser SDKs receive short-lived, scoped game and match-entry credentials only.
